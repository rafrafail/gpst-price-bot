# Структура проекта `tg_bot_template`

Сводка по папкам и ключевым Python-модулям, чтобы передать ИИ описание текущего устройства проекта и переразложить логику по новым файлам/директориям.

## Дерево верхнего уровня
```
tg_bot_template/
├── main.py                 # Точка входа: запуск бота, регистрация роутеров, middleware, команд и фонового scheduler
├── requirements.txt        # Список зависимостей (aiogram 3.22 и др.)
├── README.md               # Общее описание и установка
├── Rules.md, todo.md       # Локальная документация/тудушки
├── activation.txt          # Служебный файл (для venv)
├── bot.db                  # SQLite-база, создаётся автоматически
├── config/                 # Конфигурационные файлы (OpenRouter и тексты сообщений)
├── core/                   # Базовые сервисы и утилиты
├── features/               # Фичи бота (admin, common и др.)
├── docs/                   # Документация проекта
├── prompts/                # Markdown-промпты для LLM
├── OpenRouterMessages/     # Архив запросов/ответов LLM (json по каждому запросу)
├── logs/                   # Логи и статистика (создаются при запуске)
├── features/broadcast_media/ # Медиафайлы запланированных постов (создаются по мере работы)
└── venv/                   # Виртуальное окружение (локальное)
```

## Ключевые Python-модули

### `main.py`
- Валидирует конфигурацию, настраивает логирование, инициализирует SQLite.
- Создаёт `Bot` и `Dispatcher`, подключает middleware (логирование действий, авто-регистрация пользователей).
- Подключает роутеры: `features.common`, `features.admin.broadcast`, `features.admin.handlers`, `features.admin.scheduled_broadcast`, `core.test_markdownv2`.
- Запускает фонового воркера `features.admin.scheduler_worker.scheduler_worker` и стартует `dp.start_polling`.

### Пакет `core/`
- `config.py` — загрузка `.env`, доступ к путям, списку админов, валидация критичных переменных, создание рабочих директорий.
- `logger.py` — настройка loguru, фильтр для маскировки токенов, вывод в терминал/файл.
- `database.py` — обёртка над aiosqlite: регистрация пользователей, выборки, таблицы для запланированных постов, CRUD по расписанию.
- `llm_client.py` — клиент OpenRouter: загрузка `config/openrouter_config.json`, ретраи (tenacity), логирование запросов/ответов в `OpenRouterMessages/`, расчёт стоимости и статистика через `core.ai_stats`.
- `ai_stats.py` — учёт статистики запросов к LLM (CSV в `logs/ai_stats.csv`). 
- `markdown_v2.py` — санитайзинг/хелперы MarkdownV2, безопасная отправка сообщений.
- `message_splitter.py` — разбиение длинных сообщений и отправка чанками с MarkdownV2.
- `test_markdownv2.py` — router для теста форматирования MarkdownV2.
- `__init__.py` — пакетный инициализатор.

### Пакет `features/common/`
- `handlers.py` — общие команды `/start` и `/help`; читает тексты из `config/messages.json` (или использует дефолтные), применяет MarkdownV2 санитайзер.

### Пакет `features/admin/`
- `handlers.py` — команда `/admin`, проверка прав через `Config.ADMIN_IDS`.
- `states.py` — FSM-состояния для рассылок и расписания (admin namespace).
- `broadcast.py` — сценарий массовой рассылки (FSM): конструктор текста/медиа/кнопок, предпросмотр, отправка всем пользователям, логирование результатов в `features/admin/broadcast_logs/` (CSV + текст рассылки), обработка ошибок Markdown.
- `scheduled_broadcast.py` — сценарий планирования постов (FSM): ввод текста, JSON с медиапланом/кнопками, загрузка локальных медиа, просмотр/отмена/список постов, валидация расписания (UTC+3), запись в БД.
- `scheduler_worker.py` — фонового воркер: каждый час проверяет `scheduled_broadcasts` и публикует просроченные или текущие посты, отправляет медиа/кнопки, обновляет статусы и чистит временные медиа.
- `broadcast_logs/` — CSV и текстовые файлы логов рассылок (создаются по факту отправки).

### Другие директории/файлы
- `config/openrouter_config.json` — конфиг моделей и агентов для OpenRouter (default/agents, стоимости).
- `config/messages.json` — опциональные тексты приветствия/справки для `features.common`.
- `features/broadcast_media/` — временное хранилище локальных медиа для запланированных постов (по постам, создаётся динамически).
- `docs/` — вспомогательные заметки (например, расписание, правила).
- `prompts/` — Markdown-промпты, используемые в работе LLM (при необходимости).
- `logs/` — логи приложения и CSV статистики (создаются при запуске, путь задаётся в `.env`).

## Потоки данных (кратко)
- Пользователь → `main.py` → middleware `UserRegistrationMiddleware` → `core.database.register_user` (SQLite).
- Команды: `/start`, `/help` → `features.common.handlers`.
- Админ-команды: `/admin`, `/broadcast` → FSM из `features.admin.broadcast`; `/schedule*` → FSM из `features.admin.scheduled_broadcast`.
- LLM-запросы → `core.llm_client` → OpenRouter → логирование в `OpenRouterMessages/` + статистика `core.ai_stats`.
- Планировщик → `features.admin.scheduler_worker` проверяет БД и публикует посты в часовой сетке (UTC+3).

## Что важно учесть при реорганизации
- Сохранить разделение: `core` = инфраструктура, `features` = бизнес-фичи/роутеры.
- FSM состояния жёстко заданы в `features/admin/states.py`; маршруты привязаны к этим состояниям.
- Хранилище медиа и логов (`features/broadcast_media`, `features/admin/broadcast_logs`, `OpenRouterMessages`, `logs`) создаётся динамически — нужно учесть пути/очистку.
- Конфигурация тянется из `.env` + `config/openrouter_config.json`; список админов — `ADMIN_IDS`.

## Guidelines для переноса/реорганизации другого репозитория
Ниже — правила, чтобы ИИ мог взять чужой код и разложить его по этой структуре.

### Куда складывать что
- `core/` — инфраструктура и переиспользуемые сервисы:
  - конфиг/валидация env (`config.py`), логирование (`logger.py`), база данных (`database.py`), клиенты внешних API (`llm_client.py`, почта/оплаты и т.п.), общие утилиты Markdown/парсинга (`markdown_v2.py`, `message_splitter.py`), сбор статистики (`ai_stats.py`), общие middlewares.
- `features/` — бизнес-фичи и роутеры Aiogram:
  - одна подпапка = одна фича/домены (например, `admin`, `common`, `analytics`).
  - внутри: `handlers.py` (router и хендлеры), `states.py` (FSM), вспомогательные подмодули фичи (например, `broadcast.py`, `scheduler_worker.py`), локальные ресурсы фичи (логи, временные файлы) в поддиректории фичи.
- `config/` — статические конфиги (json/yaml) и шаблоны сообщений.
- `prompts/` — промпты/системные подсказки для LLM.
- `docs/` — документация и инструкции.
- `logs/`, `OpenRouterMessages/`, `features/broadcast_media/`, `features/admin/broadcast_logs/` — каталоги, которые должны создаваться автоматически кодом.

### Шаги миграции чужого проекта
1. Выявить инфраструктурные модули и перенести/расколоть их в `core/` (конфиг, логирование, клиенты API, DAL/ORM, общие хелперы, middleware).
2. Для каждой пользовательской области создать подпапку в `features/` и вынести туда роутеры/хендлеры, FSM-состояния и вспомогательные файлы фичи.
3. Общие утилиты разметки, отправки сообщений, пагинации, ретраев — в `core/`; специфичная бизнес-логика — в `features/<feat>/`.
4. Конфиги/шаблоны (тексты, модели LLM, ключи) — в `config/`; промпты — в `prompts/`; данные/логи — не держать в гите, создавать на лету.
5. В `main.py` оставить только wiring: валидация конфигурации, инициализация инфраструктуры, регистрация middleware/роутеров/команд, запуск scheduler’ов/фоновых задач.
6. FSM: состояния складывать в `features/<feat>/states.py` и использовать единый нейминг `FEAT__GROUP__STEP`.
7. Проверить пути создания временных директорий/логов, чтобы они опирались на `core.config.Config` и не сыпались при отсутствии папок.
