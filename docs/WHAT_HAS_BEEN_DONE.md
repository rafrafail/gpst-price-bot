# What Has Been Done

Документ описывает реализованные фичи и компоненты шаблона телеграм-бота.

## Core

- **LLMClient** — клиент для работы с OpenRouter API с ретраями, таймаутами, логированием и сохранением всех запросов/ответов
- **Статистика по ИИ-запросам** — автоматическая запись в CSV (`/logs/ai_stats.csv`) с полями: timestamp, user_id, username, model, tokens_in, tokens_out, tool, duration_s, cost_usd, prompt_preview
- **Базовая FSM-архитектура** — поддержка состояний через aiogram StatesGroup с форматом имен `FEAT__GROUP__STEP`
- **База данных пользователей** — SQLite с таблицей users (telegram_id, telegram_nickname, telegram_name, created_at)
- **Логирование** — настройка loguru с цветным выводом в терминал (при DEBUG_MODE=1) и записью в файл (при LOG_TO_FILE=1)
- **Markdown санитизация** — очистка Markdown под совместимость с Telegram (удаление HTML, таблиц, task lists и т.д.)
- **Разбиение длинных сообщений** — автоматическое разбиение текста на части с учетом лимита Telegram (4096 символов) и сохранением целостности Markdown блоков
- **Конфигурация** — централизованное управление через `.env` и `config/openrouter_config.json`

## Features

- **ADMIN** — панель администратора с командой `/admin` и проверкой прав доступа
- **BROADCAST** — модуль рассылки сообщений всем пользователям (`/broadcast`) с FSM-состояниями и inline-кнопками

## Infra

- **Структура проекта** — модульная архитектура с разделением на core/, features/, prompts/, config/, docs/
- **Промпты** — все промпты хранятся в `/prompts/*.md` с инструкциями о формате ответа (Markdown)
- **OpenRouter конфигурация** — единый реестр моделей и агентов в `config/openrouter_config.json`
- **Валидация конфигурации** — проверка обязательных переменных окружения при старте
- **Обработка ошибок** — CriticalError при нарушении правил конфигурации
