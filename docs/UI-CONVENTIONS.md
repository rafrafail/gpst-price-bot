# Правила интерфейса v2

Основа взята из поведения SlovoX, а не копированием продуктового кода. Названия
и раскладка — первая рабочая версия для проверки владельцем, не утверждённый навечно дизайн.

## Навигация

- Одно редактируемое сообщение-панель на пользователя в личном чате. При /menu не
  добавляем новое, пока старое доступно. Удалённое/недоступное меню заменяем одним новым.
- «Назад» восстанавливает родительский экран, включая страницу списка. «Главное меню»
  очищает только навигацию и текущий ввод, не черновик и не фоновую отправку.
- Предпросмотры, тестовые посты и результаты — отдельные сообщения. Нельзя редактировать
  результат в главное меню или удалять его ради красивой переписки.
- Кнопки старой панели не выполняют изменения. Действия под постом используют явный
  белый список переходов и открывают актуальное меню своего пользователя.
- /cancel отменяет только ожидаемый ввод. Выход из редактора сохраняет черновик.
- Остановка оставшейся отправки требует подтверждения и не отзывает уже отправленное.

## Редактор

Пришлите обычный пост Telegram. Храним native entities и file_id; Markdown/JSON не нужны.
Текст, вложения, кнопки, получатели и время редактируются независимо. Любая запись
черновика проверяет revision: старое сообщение не может затереть новую версию.
Поддержаны текст, фото, видео, альбом 2–10 фото/видео с одной общей подписью.
Для альбома/длинной подписи текст и кнопки идут отдельными сообщениями; предпросмотр
использует те же части, что доставка. Неподдержанные форматы явно отклоняются.

Кнопки вводятся строками `Название | https://example.com`; `;` соединяет соседей в ряд.
Разрешённые переходы: @home, @help, @example, @preferences. 0 убирает все кнопки.
Время: ДД.ММ.ГГГГ ЧЧ:ММ в явно показанном BOT_TIMEZONE. Прошлая дата отклоняется.
Список получателей показывается числом перед запуском; изменение состава требует
повторного подтверждения. Отписка проверяется ещё раз при фактической отправке.

## Надёжность и честность

Один и тот же отправщик используется в предпросмотре, тесте себе и рассылке.
Храним результат и номер следующей части по получателю. Не обещаем exactly-once Telegram:
обрыв связи после отправки или сбой контрольной записи => unknown, без автоповтора.
После перезапуска уже подтверждённые части не отправляются повторно. pause/resume
не разрешают повтор уже отправленного; retry касается только известных failed.
Отписка не отключает ответы бота; она не должна теряться от /start или нажатия кнопки.
Не показываем процент прочитавших: API подтверждает отправку, не прочтение.

## Границы

Пока только личные чаты. Группы, платежи, AI, аналитика кликов, повторяющиеся кампании,
веб-редактор и миграция старой БД не входят в эту версию. BROADCAST_ENABLED=0 скрывает
и закрывает модуль, не ломая меню и пример заметки. Тесты с HTTP-двойником не являются
живой проверкой Telegram или приёмкой удобства владельцем.
