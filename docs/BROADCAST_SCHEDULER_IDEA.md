# 📅 Идея: Scheduler для Broadcast

## 🎯 Цель

Реализовать систему планирования рассылок, которая позволит:
- Создавать посты заранее и назначать время их публикации
- Автоматически отправлять посты в указанное время
- Отслеживать статус выполнения запланированных постов
- Управлять очередью постов (редактирование, удаление, просмотр)

## 💡 Варианты реализации

### Вариант 1: SQLite База Данных (⭐ Рекомендуемый)

**Плюсы:**
- ✅ Уже используется в проекте (`bot.db`)

- ✅ Поддержка транзакций

- ✅ Простое резервное копирование (один файл)

**Минусы:**
- ⚠️ Нужно добавить новую таблицу в БД
- ⚠️ Нужно реализовать методы для работы с scheduled broadcasts

**Структура таблицы:**
```sql
CREATE TABLE scheduled_broadcasts (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    text TEXT NOT NULL,
    photos TEXT,  -- JSON массив file_id
```

### 3. Фоновый процесс (Scheduler Worker)

**Варианты реализации:**

#### A. Background Task в aiogram (⭐ Рекомендуемый)
```python
async def scheduler_worker(bot: Bot):
    """Фоновый процесс для проверки и отправки запланированных постов."""
    while True:
        try:
            # Получаем посты, которые нужно отправить сейчас
            pending = await db.get_pending_broadcasts()
            
            for broadcast in pending:
                # Проверяем, наступило ли время
                scheduled_at = datetime.fromisoformat(broadcast['scheduled_at'])
                if datetime.utcnow() >= scheduled_at:
                    # Отправляем рассылку
                    await send_scheduled_broadcast(bot, broadcast)
            
            # Проверяем каждую минуту
            await asyncio.sleep(60)
        except Exception as e:
            logger.error(f"Ошибка в scheduler_worker: {e}")
            await asyncio.sleep(60)
```

**Запуск в `main.py`:**
```python
async def main():
    # ... существующий код ...
    
    # Запускаем scheduler worker
    asyncio.create_task(scheduler_worker(bot))
    
    await dp.start_polling(bot, skip_updates=True)
```

#### B. APScheduler (Advanced Python Scheduler)
- ✅ Более продвинутый функционал (cron, интервалы)
- ✅ Поддержка timezone
- ⚠️ Дополнительная зависимость
- ⚠️ Избыточно для простых задач

**Вывод:** Для начала используем простой background task, при необходимости перейдем на APScheduler.

## 🔄 Процесс создания запланированной рассылки

1. Админ вызывает `/schedule`
2. Вводит текст (как в `/broadcast`)
3. Может добавить фото/видео/кнопки (как в `/broadcast`)
4. Выбирает дату и время публикации
5. Подтверждает создание
6. Пост сохраняется в БД со статусом `pending`
7. Scheduler worker периодически проверяет БД
8. Когда наступает время, пост отправляется через существующую логику `/broadcast`
9. Статус обновляется на `sent`, записывается `broadcast_id` и `sent_at`

   - Только UTC или с поддержкой timezone?
   - Какой формат ввода удобнее: `03.12.2025 10:00` или `2025-12-03 10:00`?

2. **Хранение медиа:**
   - Сохранять `file_id` из Telegram (проще, но может стать невалидным)
   - Или скачивать и хранить локально (надежнее, но сложнее)?

3. **Обработка ошибок:**
   - Что делать, если пост не отправился? Повторять автоматически?
   - Сколько раз повторять? С каким интервалом?

4. **Лимиты:**
   - Максимальное количество запланированных постов?
   - Минимальное время до отправки (например, не менее 1 минуты)?

5. **Права доступа:**
   - Все админы могут видеть/редактировать посты друг друга?
   - Или только создатель может редактировать?
